# Overview

The Task Producer in the Distributed Task Queue system is responsible for generating and submitting tasks into the queue (or Kafka topic) that will later be consumed and processed by the Task Workers. This service typically generates tasks either based on user inputs, scheduled jobs, or external triggers. It serves as the entry point for the system and initiates the distributed processing workflow.

# Key Responsibilities of the Task Producer:

## Task Generation:
The Task Producer generates tasks, which can be simple jobs like processing data, performing computations, or any operation that can be distributed.

It can generate tasks based on several factors, such as:
- User-triggered events (e.g., API calls to the producer).
- Scheduled jobs (e.g., periodic tasks, cron jobs).
- External inputs from other services or data streams.

## Task Submission:
- Once tasks are generated, they are serialized (using Protobuf) and published to a Kafka topic. This decouples the producer from the workers, enabling a scalable, distributed processing pipeline.
- Kafka acts as the message broker, allowing multiple Task Workers to subscribe to the task queue and consume jobs.

## Communication with Task Workers:
- The Task Producer doesn’t communicate directly with Task Workers. Instead, it relies on Kafka as the intermediary.
- Task Workers subscribe to the Kafka topic where the Task Producer publishes tasks, enabling asynchronous and distributed task processing.

## Task Metadata:
- Each task generated by the Task Producer contains essential metadata such as:
-  taskId: A unique identifier for the task.
-  taskType: A description or code indicating the type of task.
-  timestamp: The time when the task was created.
-  payload: Any additional data required for the worker to execute the task.

This metadata is encapsulated using Protobuf for efficient transmission.

## Kafka Integration:

- The Task Producer is integrated with Kafka to publish tasks to a Kafka topic (e.g., task_queue).
- Kafka provides fault tolerance and scalability, ensuring that tasks are reliably delivered to the Task Workers, even in case of network or service failures.

## Scaling and Performance:

- Since the Task Producer generates tasks and submits them to a distributed queue, it can be scaled horizontally to generate more tasks when needed.
- Scaling is especially useful when dealing with high-throughput systems where multiple instances of the Task Producer can be run simultaneously to handle more task generation requests.

# Design and Implementation of the Task Producer
## gRPC API:
The Task Producer exposes a gRPC service that allows external systems or users to submit task requests.

Protobuf Definition (example):

```proto
syntax = "proto3";

package taskproducer;

service TaskProducer {
  rpc SubmitTask (TaskRequest) returns (TaskResponse);
}

message TaskRequest {
  string taskType = 1;
  string payload = 2;  // Additional data required to process the task
}

message TaskResponse {
  string taskId = 1;    // Unique ID of the task
  string status = 2;    // Status of the task submission (e.g., "submitted")
}
```

In this example:

- The TaskRequest contains the taskType (which describes the type of task to be executed) and the payload (additional data needed by the worker).
- The Task Producer responds with a TaskResponse that includes the taskId and a status message indicating whether the task was successfully submitted.

## Task Submission to Kafka:
- After receiving a TaskRequest, the Task Producer generates a Task message, serializes it using Protobuf, and publishes it to a Kafka topic.
- Kafka Topic: The producer publishes tasks to a specific Kafka topic (e.g., task_queue) which is consumed by the Task Workers.

Example Kafka task message (Protobuf):

```proto
message Task {
  string taskId = 1;
  string taskType = 2;
  string payload = 3;
  int64 timestamp = 4;  // Time when the task was created
}
```
The task message is serialized into binary using Protobuf and sent to Kafka for consumption by the workers.

##  Service Logic:
- Receive Task Request: The gRPC SubmitTask method receives the task request.
- Generate Task: The service generates a unique taskId, attaches a timestamp, and creates a Task object that contains the task type, payload, and other relevant metadata.
- Publish to Kafka: The Task object is serialized into a Protobuf binary format and sent to the Kafka topic.

Java Code Example (TaskProducerService.java):

```java
public class TaskProducerService extends TaskProducerGrpc.TaskProducerImplBase {

    private final KafkaProducer<String, Task> kafkaProducer;
    private final String taskQueueTopic;

    public TaskProducerService(KafkaProducer<String, Task> kafkaProducer, String taskQueueTopic) {
        this.kafkaProducer = kafkaProducer;
        this.taskQueueTopic = taskQueueTopic;
    }

    @Override
    public void submitTask(TaskRequest request, StreamObserver<TaskResponse> responseObserver) {
        // Generate a unique task ID and timestamp
        String taskId = UUID.randomUUID().toString();
        long timestamp = System.currentTimeMillis();

        // Create the Task object
        Task task = Task.newBuilder()
                .setTaskId(taskId)
                .setTaskType(request.getTaskType())
                .setPayload(request.getPayload())
                .setTimestamp(timestamp)
                .build();

        // Publish the task to Kafka
        ProducerRecord<String, Task> record = new ProducerRecord<>(taskQueueTopic, taskId, task);
        kafkaProducer.send(record);

        // Send a response to the client
        TaskResponse response = TaskResponse.newBuilder()
                .setTaskId(taskId)
                .setStatus("submitted")
                .build();
        responseObserver.onNext(response);
        responseObserver.onCompleted();
    }
}
```
## Kafka Producer Setup:
The Task Producer uses Kafka to publish tasks. You need to configure the Kafka producer with appropriate settings (e.g., brokers, topic).
Example Kafka producer configuration:

```properties

bootstrap.servers=kafka:9092
key.serializer=org.apache.kafka.common.serialization.StringSerializer
value.serializer=io.confluent.kafka.serializers.protobuf.KafkaProtobufSerializer
acks=all
retries=3
```
This configuration ensures that the producer can reliably publish tasks to the Kafka topic with fault tolerance and retries.

## Task Metadata and Payload:
- Each task has metadata (e.g., task ID, task type, timestamp) and a payload (custom data needed by the Task Workers).
- The Task Workers use the taskType to determine what kind of processing the task requires, and the payload contains the data required for the task.

## Scaling and Fault Tolerance:
- The Task Producer can be scaled horizontally in Kubernetes by running multiple instances. Each instance of the producer can submit tasks independently, increasing throughput.
- Kafka ensures that tasks are reliably submitted and distributed across the Task Workers.

To scale the Task Producer service:

```bash
kubectl scale deployment task-producer --replicas=3 -n distributed-task-queue
```

# Example Workflow:
- Task Request Submission: A client or external service sends a task request to the Task Producer’s gRPC API.
- Task Generation: The Task Producer generates a task, including a unique taskId, metadata, and the task-specific payload.
- Task Submission to Kafka: The Task Producer serializes the task and publishes it to a Kafka topic (e.g., task_queue).
- Task Workers: Task Workers subscribed to the Kafka topic consume tasks and process them.
- Response to Client: The Task Producer sends a response back to the client, confirming the task submission with a taskId and status.

# Summary:
- Task Producer is responsible for generating, serializing, and submitting tasks to a distributed queue (Kafka) for processing by workers.
- It handles the task generation logic and uses gRPC for receiving task requests and Kafka for task distribution.
- The service is designed for scalability and fault tolerance, making it easy to handle high-throughput task generation in a distributed environment.
